## 1. 22 条反模式

按"出现频率 × 破坏力"排序。命中就改，不要侥幸。

| # | 反模式 | 为什么不行 | 修法 |
|---|---|---|---|
| 1 | 通用"动漫少女 + 夕阳 + 光斑" | 与歌词无关，任何一支歌都能用 | 回到意象库，用这支歌独有的名词 |
| 2 | 全程同一强度 | 没有起伏，观众 40 秒后麻木 | 做强度预算，留出 ≥5 的低点 |
| 3 | 每个镜头都有特效 | 特效互相稀释，且遮蔽结构 | 一镜 ≤2 个，至少 1/3 镜头零特效 |
| 4 | 歌词压在角色脸上 | 文字与表情互毁 | 文字退到侧带/背景层，或角色让位 |
| 5 | 浅底白字 | 直接不可读 | 换深色字，或文字区清场 |
| 6 | 结尾 fade out | 观众感觉"视频结束了"，不是"作品结束了" | 设计一个终点想法（硬切/回到首帧/一个动作） |
| 7 | 全是中景 | 平淡、没有节奏、像纪录片 | 景别跳级，加 15% 特写与 10% 大远景 |
| 8 | 母题重复但不变形 | 观众第 2 次就无视 | 三幕变形，第三次翻转含义 |
| 9 | 色板超过 8 个颜色 | 花、廉价、失去记忆点 | 3–5 组 × 5–7 角色，点缀色只有一个 |
| 10 | 没有一个 hold | 疲劳，且没有"重音" | 至少 3 个 ≥2 秒的静止/极慢 |
| 11 | 转场过多（>8 个特殊转场） | 技巧盖过内容 | 保留最好的 6 个，其余硬切 |
| 12 | 场景超过 7 个 | 每个都建不深，变成地点游览 | 合并到 3–5 个，靠时间/光区分 |
| 13 | 世界观多个反常（重力反+时间跳+颜色会说话） | 观众放弃理解 | 只保留一个反常，其余写实 |
| 14 | 字体超过 3 个家族 | 变字体样品页 | 砍到 3 个，明确各自职责 |
| 15 | 竖屏版是横屏裁的 | 构图重心全错，上下浪费 | 分镜阶段就用竖构图 |
| 16 | 前 3 秒是 logo/黑屏/缓慢淡入 | 短视频平台直接划走 | 最强的帧放第 0 秒 |
| 17 | 完全靠歌词叙事 | 静音就什么都不剩 | 画面自带叙事，文字是加成 |
| 18 | 素材白平衡不统一 | 剪在一起会跳色 | 统一一次调色/LUT |
| 19 | 角色形似既有知名角色 | 法律与口碑双重风险 | 原创设计，换个配件与配色逻辑 |
| 20 | 首尾无呼应 | 没有"完成感"，只是结束了 | bookend：同构图不同状态 |
| 21 | 镜头时长平均分配 | 机械感，与音乐脱钩 | 挂到真实拍点，长短要有差 |
| 22 | 角色表情/姿态单一 | 情绪传达失败 | 每段至少一个"新表情"或"新姿态" |

## 2. 分阶段自检清单

### P1 论点
- [ ] 一句话能说出这支片子"是什么"（不是"讲什么"）
- [ ] 这句话能否决至少一个具体做法
- [ ] 换一首歌它就不成立了
- [ ] 它暗示了一个结尾
- [ ] 能推出母题

### P2 系统
- [ ] 主形状 + 副形状，两者有关系
- [ ] 点缀色只有一个，且只在一个物件上
- [ ] 主体的明度与背景差 ≥30
- [ ] 全片材质隐喻只有一种
- [ ] 字体 ≤3 家族，各自职责明确
- [ ] 歌词色方案按"深底/浅底"分开定了
- [ ] 世界观只有一个反常维度
- [ ] 场景 3–5 个，每个能提供 ≥3 种景别

### P3 时间表
- [ ] 分镜时间点来自真实音轨/BPM
- [ ] 转折点有明确时间，各部门对齐
- [ ] ≥3 个 hold，其中一个是副歌前
- [ ] 6–10 个招牌瞬间已标注
- [ ] 特效总量：一镜 ≤2 个
- [ ] 素材复用比例 ≥40%
- [ ] 转场数量在预算内
- [ ] `shotlist_check.py` 无红色告警

### P4 观看
- [ ] 手机尺寸下主体可辨
- [ ] 静音能看懂
- [ ] 前 3 秒有钩子
- [ ] 首尾呼应
- [ ] 去色后主体仍突出
- [ ] 暗部在压缩后还有层次（可用低码率导一版试）

## 3. 评审三栏法

用户拿成片/分镜来问"怎么样"时，**不要列十个问题**。用三栏，每项一句理由，最后只指出**一个**结构性问题。

```markdown
# 评审 — <作品>

## 保留（这些是对的，别改）
- <具体到秒/镜> —— 因为 <理由>

## 修（方向对，执行需要调整）
- <具体到秒/镜> —— 问题：<一句话> → 改法：<一句话>

## 砍（建议删除）
- <具体到秒/镜> —— 因为 <它伤害了什么>

## 唯一的那个结构性问题
<一句话。如果只改一件事，就改这个。>
```

**为什么只给一个问题**：人一次只能改一件事。列十个，用户会全部忽略或全部改坏。

判断"结构性问题"的三个候选（按优先级）：
1. 没有论点 → 所有"小问题"都是它的症状
2. 没有强度起伏 → 改这一点，其他问题会自动减轻
3. 首尾不呼应 → 改这一点，"完成度"立刻上一档

## 4. ROI 排序

按"每小时投入带来多少提升"排序。工期紧就从上往下做：

| 排序 | 动作 | 成本 | 提升 |
|---|---|---|---|
| 1 | 副歌前加 1–2 秒静止 | 极低 | 极大（副歌冲击翻倍） |
| 2 | 最强帧放到第 0 秒 | 极低 | 极大（完播率） |
| 3 | 首尾 bookend | 低 | 极大（完成感） |
| 4 | 主角与背景拉开明度差 | 低 | 大（解决"不突出"） |
| 5 | 点缀色只留一处 | 低 | 大（注意力聚焦） |
| 6 | 母题第三次变形 | 低 | 大（记忆点） |
| 7 | 切点对齐真实重拍（提前 1–2 帧） | 低 | 大（"专业感"的来源） |
| 8 | 加颗粒 + 暗角 + 线抖动 | 低 | 中高（去 AI 感/去 PPT 感） |
| 9 | 景别跳级（大远景直切特写） | 低 | 中高 |
| 10 | 一个长镜（20 秒不切） | 高 | 高（招牌瞬间） |
| 11 | 一个 3D 空间段落 | 高 | 中高 |
| 12 | 手绘逐帧段落 | 极高 | 高（但通常做不完） |

**结论**：前 9 项全是低成本的。所以"好看"的瓶颈几乎从来不是技术，是**有没有做这 9 件事**。

## 5. 只有一天时怎么办

给工期极紧的用户的降级方案。目标是"结构成立"，牺牲"精致度"。

**砍掉的**：3D、手绘逐帧、原创角色多姿态、复杂运镜、多场景
**保住的（按顺序）**：
1. 论点（哪怕只有一句）
2. 强度起伏：至少一个安静段 + 一个爆发段
3. 6 个招牌瞬间（用最便宜的那几个：母题回收、首尾 bookend、色彩跳变、文字建筑）
4. 一个点缀色
5. 颗粒 + 暗角（十分钟的活，效果显著）

**方案**：3 个场景 × 5 个角色姿态 × 40 个镜头，用静止画 + 运镜（推/拉/摇/视差）+ 转场完成 80%。文字层承担情绪。**这套方案做得好，比 60 个粗糙的原创镜头的成片更好看。**

## 6. 交给制作层的清单

本 skill 结束时，交付给制作流程（AE 工程 / 引擎 / Blender / 出图流水线）的东西：

| 文件 | 内容 | 谁用 |
|---|---|---|
| `docs/BRIEF.md` | 曲目、约束、意象库 | 全体 |
| `docs/VISUAL_BIBLE.md` | 论点、五条规则、色板、母题、字体、授权 | 美术/出图 |
| `docs/color_script.png` | 段落色彩走向 | 调色/背景 |
| `docs/SHOTLIST.csv` | 逐镜参数 | 剪辑/合成 |
| `assets/` | 色板 JSON、参考图、字体清单 | 出图/合成 |

### 命名与组织约定
```
项目/
├── docs/
│   ├── BRIEF.md
│   ├── VISUAL_BIBLE.md
│   ├── color_plan.json        # color_script.py 的输入
│   ├── color_script.png
│   └── SHOTLIST.csv
├── assets/
│   ├── bg/                    # 背景，按场景命名 bg_<地点>_<时间>.png
│   ├── char/                  # 角色，char_<姿态>_<表情>.png
│   ├── fg/                    # 前景
│   └── fonts/
└── ...
```

### 验收标准（写进 VISUAL_BIBLE，制作时逐镜对照）
1. 主体与背景明度差 ≥30
2. 一镜特效 ≤2 个
3. 歌词不压脸
4. 浅底场景用深色字
5. 切点在真实拍点上（误差 ≤2 帧）
6. 全片点缀色只出现在一个物件上
7. 首尾构图呼应

制作层交付后，回到 P4 用 §2 的"观看"清单验收。不合格的镜头回到分镜改，不要在现场救——**现场救出来的镜头通常是全片最丑的那一个**。
