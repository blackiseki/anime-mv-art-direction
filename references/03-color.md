# 03 — 色彩：色彩脚本、明度结构、色板纪律

## 1. 色彩脚本不是配色方案

**配色方案**回答"这支片子用什么颜色"。
**色彩脚本（color script）**回答"第几秒是什么颜色，为什么变"。

前者是静态的，后者是**时间的**。MV 是时间艺术，所以只有后者有用。

一张合格的色彩脚本长这样（每一格是一段，横向是时间）：

```
Intro   ─────────────────────  单一冷灰，只留一个暖点
Aメロ   ─────────────────────  灰蓝稳定，饱和度低
Bメロ   ─────────────────────  蓝开始偏紫，明度下降
サビ1   ─────────────────────  满色：紫+橙，对比拉满
間奏    ─────────────────────  跳出色板（白+黑，纯图形）
2番     ─────────────────────  加一个变量：雨，色相不变但明度更低
Cメロ   ─────────────────────  抽色，接近单色（只剩一点肤色）
ラスサビ ────────────────────  前段的色"着火"：加亮、加饱和、加面积
Outro   ─────────────────────  回到 Intro 的色，但暖点已经熄灭
```

用 `scripts/color_script.py` 可以直接把这个渲染成图：

```bash
python scripts/color_script.py color_plan.json -o docs/color_script.png
```
JSON 格式见脚本头部注释（`title` / `bpm` / `sections[]`，每段给 `name`, `start`, `end`, `colors`, `note`）。

**判断标准**：把色彩脚本竖着剪开、打乱顺序，如果分不出先后，说明它只是配色方案，不是脚本。

## 2. 三种叙事型

先选型，再选色。型决定"颜色怎么变"。

### 2.1 渐变型 Progression（最常用）
同一个色相/色温沿时间单向推进：黄昏 → 夜 → 黎明；春 → 夏 → 秋。
- **优点**：观众潜意识能感到"在前进"，不需要解释。
- **做法**：定 3–5 个锚点色板，段落之间是**渐变**（可以是硬切，但色板本身在演化）。
- **陷阱**：推进太慢会显得没变化。每两个锚点之间必须有可见的明度差，光靠色相微调不够。

### 2.2 撞击型 Collision（最有冲击）
段落之间硬切到互补/对立色，不做过渡：暖 → 冷 → 暖。
- **优点**：切点本身就是重音，可以省掉一个特效。
- **做法**：只在**音乐的重拍**上撞。撞色前必须有至少 3 秒的稳定，否则观众会以为出错了。
- **陷阱**：撞多了会碎。一支 3 分钟的片子撞 4–6 次是上限。

### 2.3 循环型 Loop（最有完成感）
出发和回到同一个色板，但**明度或饱和度不同**（回去的地方已经不是原来的地方）。
- **优点**：成本极低，但"完成度"提升巨大。
- **做法**：Intro 和 Outro 用同一个色板配方，Outro 把其中一个色的面积或亮度改掉。
- **陷阱**：改得太少观众看不出来。至少改 30%（比如暖点从亮橙变成灰橙，或者干脆消失）。

**混合用法**：主型 + 局部型。例如整体渐变（黄昏→夜），但 Cメロ 用一次撞色（红）来标记转折。**不推荐三种平均用**——那就没有型了。

## 3. 明度结构优先

这是二次元 MV 最常被忽略、也最致命的一项。

**核心事实**：人眼先看明度对比，再看颜色。一张颜色很漂亮但明度均匀的画面，观众的眼睛**无处停**，会觉得"糊""没有重点""不好看但说不上哪里"。

### 3.1 三层明度

每个画面必须有三个可分辨的明度层（用 0–100 的明度值估）：

| 层 | 明度范围 | 内容 |
|---|---|---|
| 暗部 | 10–35 | 阴影、背景深处、剪影 |
| 中间 | 40–65 | 环境、地面、大部分背景 |
| 亮部 | 75–95 | 光源、天空、脸的高光、主体 |

**主角必须和它身后的区域差至少 30 个明度值**。这一条能解决 80% 的"人物不突出"问题。

### 3.2 两种基础明度构图（选一种作为全片主调）

**低调（low-key）**：暗部占 60% 以上，亮部很少但很亮。→ 神秘、孤独、戏剧性、黄昏/夜。
**高调（high-key）**：亮部占 60% 以上，暗部很少。→ 清透、青春、日常、正午/雪/海。

**注意**：二次元 MV 有 80% 默认用低调，因为低调容易"好看"。如果你的歌是明快的，硬上低调会变成"用夜景拍青春片"的别扭感。高调片在技术上更难（见 §7），但辨识度高得多。

### 3.3 两个测试（做完就做，别等成片）

1. **去色测试**：把画面转成灰度。主体还看得见吗？看不见 → 明度结构失败，加对比或改光源位置。
2. **缩略测试**：把画面缩到 200px 宽（手机上的大小）。还能看出在画什么吗？看不出 → 细节太碎，简化。

这两个测试比任何配色理论都实用。

## 4. 色板构造

### 4.1 结构

一支片子需要 **3–5 组色板**（对应段落），每组 **5–7 个角色**：

| 角色 | 作用 | 说明 |
|---|---|---|
| 天空/背景主 | 占画面面积最大 | 定基调 |
| 环境副 | 地面、建筑、室内 | 和主色差 1–2 档明度 |
| 主体固有色 | 头发、衣服 | 必须与背景有明度差 |
| 高光/光源 | 灯光、太阳、发光物 | 最亮 |
| 阴影 | 阴影染色 | 不是黑色，是带色相的暗色 |
| **点缀色** | 唯一的高饱和色 | 见 §5 |
| 反相/余像 | 负片、残影、闪光 | 用于极端瞬间 |

### 4.2 面积比例

**7 : 2 : 1**（主色 : 次色 : 点缀）。或 **6 : 3 : 1**。
点缀色占 10% 左右时最有效；超过 20% 就不再是"点缀"，会抢主色。

### 4.3 饱和度纪律

同一画面里，**高饱和只允许出现在一处**。其余全部压到中低饱和。

原因：饱和度是相对感受。画面里有两个高饱和色，它们会互相削弱，观众感到"廉价/花"。
（例外：故意做"糖果色爆炸"的风格，例如某些电波曲 PV——但那是**整体高饱和**的统一处理，不是局部几个高饱和。）

### 4.4 阴影要染色

纯黑阴影（#000）在二次元色彩里几乎总是错的。阴影用**主色的补色方向压暗**：
- 暖光 → 冷紫/冷蓝的阴影
- 冷光 → 暖褐的阴影
- 这一步能让画面立刻"专业"起来，成本为零

### 4.5 只属于这首歌的一个色

最后给用户一个提问：**"如果这支片子只能记住一个颜色，是哪个？"**
答案应该是点缀色。它要出现在最能被记住的三个时刻（首、中、尾各一次）。

## 5. 点缀色纪律

点缀色是全片最有力的工具，因为它**可以被"出场"**。

三条纪律：
1. **只出现在一个物件上。**（残光：朱红的丝带。全片唯一的红。）
2. **它有状态变化。** 开场很小 → 中段变大/变多 → 结尾消失或变成别的东西。
3. **它不许随便加。** 一旦出现第二处红，前面积累的所有注意力立刻摊薄。

**为什么有效**：观众会自动追踪"唯一的不同"。这是免费的视觉引导，比任何运镜都强。

**用法示例**：
- 灰色世界里唯一的红是她的围巾 → 中段围巾被风吹走 → 结尾它在别人身上
- 冷蓝世界里唯一的黄是远处的窗灯 → 逐渐变近 → 最后发现是自己家的灯

## 6. 色温叙事

色温（冷暖）比色相更能表达"心理距离"：

| 关系 | 常用处理 |
|---|---|
| 亲近 / 现在 / 安全 | 暖（3200–4500K 的橙黄） |
| 疏远 / 过去 / 冷漠 | 冷（7000K+ 的青蓝） |
| 回忆 | 暖 + 降饱和 + 加颗粒（不是加棕，是**褪色**） |
| 危险 | 冷底 + 一处暖（警灯）或 暖底 + 一处冷（月光） |
| 谎言 / 不真实 | 冷暖同画面且不调和（绿脸 + 橙背景） |

**最有效的一招**：同一画面里，人物的暖度与环境的冷度**反向变化**。
- Aメロ：环境冷，人物暖（她还有生气）
- Cメロ：环境暖，人物冷（她已经冷了）
观众不会意识到发生了什么，但会感到"变了"。这比换整个色板省事得多。

## 7. 高键与低键：歌词可读性

**浅底白字是二次元 MV 的头号事故。** 一个有云的白天、一片雪地、一片海——白字直接消失。

在 P2 就要定"这支片子的歌词用什么色"，而不是等做到那一镜再救。

| 底色 | 歌词色 | 手法 |
|---|---|---|
| 深（夜/室内/暗调） | 近白、象牙白、浅金 | 全片默认 |
| 浅（白天/雪/海/白背景） | 深色（墨蓝/深褐/黑） | 最稳，且更有"印刷品"质感 |
| 明暗都有 | 分镜标注每镜用哪套 | 不要一个方案打天下 |
| 极复杂（碎色背景） | 加托底：暗角、色块、渐变带、模糊层 | 文字区先"清场"再放字 |

**检查方法**：把字所在区域单独截图，去色，算文字与底的明度差。**差 < 40 就是不可读**，必须处理。

## 8. 可读性（不只是字）

整套画面的"可读性"包括：
- **主体可辨**：缩略测试能看出人物在哪
- **动作可辨**：这个镜头在发生什么，不需要解释
- **情绪可辨**：不需要台词也知道她难过/生气/放松

三个都可辨，才叫"看得懂"。MV 允许抽象，但不允许"看不懂"——抽象是设计，看不懂是失败。

## 9. 七个技术陷阱

1. **暗部糊成一团。** 视频压缩（尤其平台二次压缩）会把 5%–15% 明度的细节吃掉。暗部里不要放关键信息，暗部层次至少留 3 档。
2. **渐变出现色带（banding）。** 大面积天空渐变在 8bit 编码下必然起带。解决：加 1–3% 的颗粒/噪点抖动，或用噪声遮罩。
3. **互补色振动。** 纯红压纯绿、纯蓝压纯橙，边缘会产生视觉抖动（刺眼）。要么降低其中一方的饱和度，要么用明度差隔开。
4. **高饱和大面积疲劳。** 全屏高饱和超过 3 秒，观众开始不适。大色块用中饱和，小面积才用高饱和。
5. **白闪（flash to white）滥用。** 连续白闪在快节奏下会引发不适，且平台压缩后变成一片死白。改为**色闪**（闪到主色/点缀色）更高级也更安全。
6. **暖色统一 = 廉价。** 全片只用橙+黑会显得像滤镜。至少要有冷暖对抗。
7. **不同素材的色温不统一。** 用 AI 出图或素材拼贴时，每张图白平衡不同，剪在一起会跳。统一做一次 LUT 或分级。

## 10. 工作流

```
1. 定叙事型（渐变/撞击/循环）        → 一句话
2. 定明度基调（低调/高调）           → 决定后面所有技术参数
3. 定 3–5 组色板（每组 5–7 角色）    → 写进 VISUAL_BIBLE
4. 定点缀色 + 它的三个出场时刻        → 一句话
5. 分配段落                        → color_plan.json
6. 出色彩脚本图                     → scripts/color_script.py
7. 做去色测试 + 缩略测试             → 修
```

**交给用户的确认话术**（3 行以内）：
> 色彩走"渐变型"：黄昏 → 夜 → 黎明，低调为主。四组色板，点缀色只有一个——她手腕上的红绳，出现在开场、副歌前、结尾三次，结尾时它断了。这样观众会一直盯着它。

**不要**给用户"你想要什么颜色"这种问题。给色板图，让他选。
